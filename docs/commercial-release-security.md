## Remaining findings and exposure boundaries

After: 9 package findings = 0 critical, 5 high, 4 moderate, 0 low. Independent `npm audit --omit=dev` reports only 2 moderate (ExcelJS / UUID), zero critical/high/low.

The five high findings are the one unpatched braces vulnerability propagated through the dev-only ESLint chain above. No reachable production critical/high remains in this audit. They are not suppressed, nor claimed patched. Reassess if runtime starts accepting glob patterns or lint becomes remotely callable.

The four moderate package findings are uuid 8.3.2, exceljs 4.4.0, hyperid 3.3.0 and autocannon 8.0.0 (propagated UUID advisory). The vulnerable UUID calls are v3/v5/v6 with an output buffer; ExcelJS uses uuid.v4() with no buffer for conditional-format identifiers. Hyperid uses crypto.randomUUID where available, otherwise v4; autocannon is dev/load-only. No application import calls vulnerable UUID APIs. Upgrading UUID across majors would break ExcelJS's supported dependency range/module contract and is not justified to erase counts. Runtime-installed ExcelJS remains documented and tested; this assessment is specific to current callers.

Next protects the entire auth/API/payment server, so payment exposure was real before the framework fix even though Stripe 23.0.0 and Node crypto had no audit findings. Signature verification still uses official constructEvent on raw request.text(), timestamp tolerance, TEST/live rejection and a durable idempotent provider ledger. No payment algorithm, raw-body handling, prices, SQL or authorization code changed.

Uploads: PDF (pdf2json), DOCX (mammoth), DOC (word-extractor), XLS/XLSX (SheetJS/ExcelJS), XML (fast-xml-parser), CSV and image/HEIC parsing were traced from extraction callers. No critical/high audit finding in these parsers besides sharp and patched glob dependencies. libheif-js used by heic-decode resolves 1.23.2, not an older vulnerable decoder. Report URL imports retain Node URL/DNS SSRF guards, 20 MB streamed cap and timeout. Upload UI's 20 MB limit is client-side; it is not used as evidence that decoder vulnerabilities are unreachable. General parser resource isolation/decompression budgets are not established by npm audit and remain a separate hardening concern.

Client PDF generation uses html2pdf.js / jsPDF; DOMPurify low advisory remediated. HTML content rendering does not introduce a new parser or payment input path in this change. Medical Motion sharp decoders retain pixel limits, allowed-output containment and trusted overlay construction. Worker SQL/leases/fencing, Blender/FFmpeg invocation and SCM implementation are unchanged. Worker packaging/host regression covers the patched tree; physical Blender, FFmpeg and SCM are not unnecessarily rerun.
