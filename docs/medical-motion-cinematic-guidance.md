# Medical cinematic guidance v1

The guidance compiler emits immutable planning SceneDefinitions and the existing
SceneSequenceDefinition. It creates no parallel renderer, queue, storage or orchestrator.
Plans are not compiler-issued MedicalScene capabilities or trusted source selections.
Existing clinical, source-profile, asset, ownership and timeline gates remain mandatory.

HEART_MASTER_VISUAL_V1 is the external establishing reference. The owner-approved
HEARTBEAT_MOTION_MASTER_V1 is INTERNAL_CUTAWAY_HEARTBEAT_MASTER, from a separate GLB.
Native action test (0–24) is sampled at 24 fps as frames 0–23 and repeated six times.
The motion lock pins the polished configuration and builder. It references the existing
visual lock; it copies no hero geometry. Owner visual approval is not legal or medical approval.

ESTABLISH → ORIENT → APPROACH → FOCUS → EXPLAIN → REORIENT is the initial six-phase
recipe grammar. Camera settings include duration, coverage, context margin, zoom ratio,
proximity, easing and clipping prohibition. The heart reference recipe is 11.5 seconds.
Its explicit fade-through-neutral boundary separates the external and internal sources.
No geometry blending, morphing, retargeting, diagnosis or disease-driven rhythm is permitted.

AnatomicalAppearanceProfile and cinematic scene contracts are organ-generic; only the
heart implementation exists. Anatomical base appearance preserves source texture meaning;
educational highlighting is temporary attention, not pathology or real tissue color.
HEART_APPEARANCE_PROFILE_V1 references the locked visual presentation. Source colors on
the cutaway are conventional source encoding, not universal biological RGB facts.
Presentation modes affect label density and attention only. Music is optional/ducked for
education previews and disabled for clinical review. Narration duration can determine a
planning scene's duration using a reference, never arbitrary patient text in a reuse key.

Current source-profile identities in this plan are explicitly UNREGISTERED descriptors,
not registry entries. Current master assetVersion values are visual roles, not runtime
OrganModule versions. SourceProfile registry currently requires supported structures;
neither visual master has separately validated canonical addressability. All structure
targets and enabled highlights therefore fail closed. Whole-organ and whole-cutaway focus
are allowed. No anatomy IDs or wall/tissue equivalences are invented to satisfy a registry.

Execution remains blocked until exact modules, source-coherent opaque profiles and safe
camera mappings exist. A future adapter must independently use existing trusted scene
compiler/orchestration APIs; it cannot execute this plan's JSON as authority. Existing
Timeline V2 also remains 720p/25 fps: no silent 1080p/24 fps production upgrade is made here.
The optional evidence is a deterministic plan and storyboard from the existing locked
masters, rather than a claim that gated orchestration or controlled camera motion ran.
Advanced DOF/opacity/highlight effects remain specification options requiring separate
source-supported safety review, not active shader or pathology implementations.

Reproducibility includes recipe/guidance/appearance versions, exact master lock hashes,
asset role/hash, pending source-profile identity, camera, durations, targets, output/fps,
language, slots/references, music, explicit boundaries and internal-review disposition.
All current assets remain patientFacing=false with licensing/provenance unresolved.
